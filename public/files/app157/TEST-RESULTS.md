# نتائج التحقق — الإصدار 1.0

أُجري التحقق بتاريخ 16 نوفمبر 2026.

## النتيجة

**نجحت 21 حالة اختبار وظيفي آلي، دون فشل أو استثناءات JavaScript أثناء هذه الحالات.** نجح فحص صياغة الملفات الثمانية بـ `node --check`.

بيئة التحقق: Node.js 24، وjsdom 26.1.0. يشغّل الاختبار ملفات التطبيق الفعلية ويستخدم النماذج والأزرار والأحداث في DOM. لا يتطلب التطبيق Node.js عند استخدامه.

## الحالات التي نجحت

1. الحالة الابتدائية: 3 موديولات، 13 مهارة، لا نتائج مستخدم مصطنعة.
2. التنقل بين جميع الأقسام وتبديل النمط مع بقاء بيانات المشروع.
3. فلترة المهارات والبحث فيها.
4. إكمال الأنشطة الثلاثة عشر من نماذجها، بما فيها الترتيب والتصنيف والتحدي والمراجعة.
5. تصعيد الدعم بعد الأخطاء، تفسير البدائل، وتثبيت نتيجة المحاولة الأولى رغم الإعادة.
6. استبعاد القرارات المسبوقة بتلميح من مؤشر الاستقلالية، وعدم اعتماد النص تلقائيًا.
7. فصل الأدلة الرقمية عن درجات القرارات الأكاديمية.
8. فحوص المراحل السبع والانتقال بينها واعتمادها.
9. استمرار مدخلات المراحل وإظهار تعليمات المعلم للطالب.
10. إضافة وحذف وتحرير المصادر والمعلومات والبيانات، واشتراط ربطها بمصدر.
11. تحديث المعاينة النصية، ترتيب وحذف العناصر، تبديل القالب، وإبطال المراجعة عند التعديل.
12. اشتراط الدرجة اليدوية ودليلها في بطاقة التقدير.
13. نقل مسودات التدريب إلى الخطة دون استبدال الحقول المكتوبة.
14. دورة حفظ واستعادة JSON مع المراحل والمنتج ومحاولات التدريب.
15. رفض JSON غير المتوافق، الصور غير المقبولة، تعديل prototype، أعداد غير صالحة، وتزوير نتيجة محاولة.
16. عرض HTML المدخل كنص، ومنع الروابط التنفيذية والألوان المحقونة.
17. بناء أقسام التقارير الأربعة مع escaping وملاحظة طبيعة المؤشرات.
18. تحويل قيم الجداول الطويلة إلى كتل فقرات قابلة للتوزيع.
19. إنشاء ملف JSON versioned قابل للقراءة والتحقق، وبدء جلسة جديدة بلا نتائج قديمة.
20. غياب التخزين الدائم والاتصالات الخلفية والمكتبات البعيدة ومعالجات الأحداث inline عن كود التطبيق.

21. منع حفظ ملف يتجاوز الحد المدعوم للاستيراد كي لا ينتج ملف حفظ غير قابل للاستعادة.

هذه الاختبارات تستخدم بيانات اصطناعية داخل الاختبار فقط. لا تُحمّل بيانات الاختبار إلى جلسة المستخدم، ولا تظهر كإحصاءات جغرافية حقيقية.

## فحوص الحزمة

- جميع مسارات الملفات المشار إليها في HTML موجودة.
- جميع مكتبات التشغيل والخطوط محلية ومرفقة.
- أرشيف ZIP سليم ويمكن استخراجه.
- لا مجلد node_modules ولا خادم ولا بيانات مستخدم ضمن الحزمة.
- توثيق المكتبات وتراخيصها مرفق.

## ما لم يُختبر في متصفح فعلي

أدوات التحكم بالمتصفح لم تكن متاحة في جلسة التنفيذ. لذلك **لم تُفتح مخرجات PDF أو PNG الصادرة عن التطبيق، ولم تُختبر الطباعة أو التنزيل أو التصيير الفعلي للرسوم والخط أو نقاط كسر الواجهة على الهاتف**. بُني كود هذه الوظائف، وفُحصت صياغته ومحتوى التقارير ومسارات الحالة، لكن jsdom لا يملك محرك تخطيط أو canvas مماثلًا للمتصفح.

لا يتضمن التقرير ادعاء نجاح هذه الفحوص. يظل قبولها البصري النهائي بحاجة إلى متصفح المستخدم أو منصة الاختبار.

## قائمة الفحص اليدوي المقترحة

افتح التطبيق في متصفح حديث بعد فك الحزمة:

- [ ] افتح `index.html` دون إنترنت، وتحقق من الخط والأيقونات.
- [ ] جرّب التدريب الصحيح والخاطئ والتلميحات على الكمبيوتر والهاتف.
- [ ] نفّذ مشروعًا ببيانات موثقة وصورة محلية.
- [ ] صدّر المشروع PDF وافتحه: الغلاف، الخطة، المصادر، الرسم، الصور، النتائج والبطاقة، دون قطع حروف أو عناصر.
- [ ] صدّر الملصق PNG وافتحه وتحقق من عرضه 2000 بكسل.
- [ ] صدّر بطاقة التقويم وتقرير الأداء وخطة التدريس PDF.
- [ ] افتح الطباعة واختر A4 وتحقق من الهوامش والخلفيات.
- [ ] احفظ JSON، أعد تحميل الصفحة، واستورده؛ تحقق من الصورة والمصادر والنتائج.
- [ ] جرّب لوحة المفاتيح فقط: Tab، Enter، وأزرار ترتيب العناصر.
- [ ] افحص العرض عند 390 و768 و1440 بكسل، وخاصة الجداول والمراحل.
- [ ] جرّب التنزيل والطباعة داخل iframe بعد ضبط صلاحيات المنصة.

## إعادة تشغيل الاختبارات

```sh
cd tests

npm test
```

تشغيل اختبارات التطوير اختياري، ولا يدخل ضمن متطلبات تشغيل الأداة للمعلم أو الطالب.
